ЗАПУСК МОЕЙ ВЕРСИИ STREAM С КОМПИЛЯТОРОМ IBM XL НА POLUS

Важно: stream.cpp написан на C++. Поэтому нужен xlC_r или xlc++_r.
Команда xlc_r предназначена для языка C и не должна линковать этот файл.

Локальная папка Windows:
C:\Users\aypir\source\repos\Research\polus

Та же папка в WSL:
/mnt/c/Users/aypir/source/repos/Research/polus

Удалённая папка:
~/stream-polus-xl


1. Открыть WSL и проверить закрытый ключ

chmod 600 ~/.ssh/id_rsa_hpc
ssh -i ~/.ssh/id_rsa_hpc edu-cmc-sqi26-11@polus.cs.msu.ru

После успешного входа выйти обратно в WSL:

logout


2. Создать отдельную папку для XL-версии на Polus

ssh -i ~/.ssh/id_rsa_hpc edu-cmc-sqi26-11@polus.cs.msu.ru \
  'mkdir -p ~/stream-polus-xl/jobs ~/stream-polus-xl/build ~/stream-polus-xl/results ~/stream-polus-xl/logs'


3. Перейти в локальный проект

cd /mnt/c/Users/aypir/source/repos/Research


4. Передать исходники и LSF-задания

scp -i ~/.ssh/id_rsa_hpc \
  polus/stream.cpp polus/run.py polus/plot.py polus/POLUS_XL_INSTRUCTIONS.txt \
  edu-cmc-sqi26-11@polus.cs.msu.ru:~/stream-polus-xl/

scp -i ~/.ssh/id_rsa_hpc -r polus/jobs \
  edu-cmc-sqi26-11@polus.cs.msu.ru:~/stream-polus-xl/


5. Подключиться и подготовить файлы

ssh -i ~/.ssh/id_rsa_hpc edu-cmc-sqi26-11@polus.cs.msu.ru
cd ~/stream-polus-xl
sed -i 's/\r$//' stream.cpp run.py plot.py jobs/*.sh jobs/*.lsf

6. Проверить IBM XL C++

xlC_r -qversion

На Polus установлена версия IBM XL C/C++ 13.1.6, а команда xlC_r уже
доступна через PATH. Дополнительный поиск компилятора не требуется.


7. Удалить только старые результаты XL-прогона

rm -f build/stream_xl
rm -f results/*.csv results/*.svg results/*.txt
rm -f logs/*.out logs/*.err


8. Собрать программу на вычислительном узле c4

bsub < jobs/build.lsf

Проверять состояние:

bjobs
bjobs -a | head -20

После DONE посмотреть отчёт:

tail -100 $(ls -t logs/build.*.out | head -1)
cat $(ls -t logs/build.*.err | head -1)

В конце stdout должны появиться четыре CSV-строки пробного теста Copy, Scale,
Add и Triad. Файл err должен быть пустым.

Проверить исполняемый файл:

ls -lh build/stream_xl
file build/stream_xl

Фактическая команда сборки печатается в build-логе. Она имеет вид:

xlC_r -O4 -qarch=pwr8 -qtune=pwr8 -qsmp=omp \
  -qlanglvl=extended0x -qmaxmem=-1 stream.cpp -o build/stream_xl


9. Запустить полный тест

bsub < jobs/run_all.lsf

Запомнить напечатанный JOBID. Проверять состояние:

bjobs
bjobs -a | head -20

Если задание находится в PEND:

bjobs -p
bjobs -l JOBID

Смотреть ход работы:

tail -f logs/all.JOBID.out

Полный прогон включает 8 конфигураций:
1core, 2cores, 4cores, 6cores, 8cores, 10cores, 20cores, 20cores_smt2.
Для каждой конфигурации проверяются 40 размеров N и четыре операции.
Каждая операция для каждого N измеряется не менее 2 секунд.


10. Проверить завершённый прогон

bjobs -a | head -20
tail -50 logs/all.JOBID.out
cat logs/all.JOBID.err

Нормальный статус: DONE. Файл err должен быть пустым.

Проверить CSV:

ls -lh results
wc -l results/all_results.csv
head -5 results/all_results.csv

Ожидается 1281 строка: заголовок и 1280 результатов.
В столбце compiler должно быть IBM_XL_C++.

13. Что делают основные флаги XL

-O4                  включает высокий уровень оптимизации XL.
-qarch=pwr8          создаёт команды для архитектуры POWER8.
-qtune=pwr8          настраивает порядок и выбор команд для POWER8.
-qsmp=omp            включает только явно написанный OpenMP.
-qlanglvl=extended0x включает возможности C++11 старого XL.
-qmaxmem=-1          не ограничивает память, доступную оптимизатору.

Привязка потоков не передаётся XL через переменные окружения. Как и раньше,
run.py передаёт список логических CPU в stream.cpp, а stream.cpp закрепляет
каждую OpenMP-нить через sched_setaffinity(). Все задания закреплены за узлом
polus-c4, поэтому результаты разных запусков не смешивают разные узлы.
